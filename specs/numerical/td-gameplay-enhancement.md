## 1. 武将技能蓄力（US-A1）

### 1.1 体验目标

> 每波战斗中，玩家有 **2-3 次有意义的手动操作时机**；Idle 模式下自动释放兜底。

### 1.2 核心公式

#### 蓄力时间

```
chargeTime(hero) = BASE_CHARGE_TIME / (1 + heroSkillCdReduction)
```

| 参数 | 类型 | 值 | 取值范围 | 说明 |
|------|------|-----|---------|------|
| `BASE_CHARGE_TIME` | 常量 | **10** 秒 | — | 沿用 `HERO_SKILL_INTERVAL`，保持向下兼容 |
| `heroSkillCdReduction` | 浮点 | 默认 0 | [0, 0.5] | 来自武将等级 / 装备 / 羁绊加成；上限 50% |

- **Lv1 普通武将**：chargeTime = 10 / (1+0) = **10s**
- **Lv50 满级 + 号令台羁绊**：chargeTime = 10 / (1+0.15+0.15) = **7.7s**

#### 手动释放加成

```
manualDamage = heroAtk × HERO_SKILL_COEFFICIENT × MANUAL_SKILL_BONUS
autoDamage   = heroAtk × HERO_SKILL_COEFFICIENT × 1.0
```

| 参数 | 值 | 说明 |
|------|-----|------|
| `MANUAL_SKILL_BONUS` | **1.5** | 手动释放伤害为自动的 150%（+50% 加成） |

**推导**：PRD KPI 要求"手动释放提供50%伤害加成"（§1.5），故取 1.5×。偏差容许：±5%。

#### 自动释放超时

| 参数 | 值 | 说明 |
|------|-----|------|
| `AUTO_RELEASE_TIMEOUT` | **5** 秒 | 蓄满后等待 5s，若玩家未操作则自动释放（无加成） |

**推导**：

- 波次约 60s，蓄力 10s → 首次可释放在 t=10s
- 若玩家未操作，t=15s 自动释放
- 下次蓄满 t=25s，自动释放 t=30s → 每 15s 一个自动周期
- 60s 内约 4 个自动周期/英雄，3 英雄 = 12 次自动
- 玩家注意力约 30-50% 的释放会是手动 → **3-6 次手动/波** → 满足"2-3 次有意义操作"目标

### 1.3 边界行为

| 场景 | 行为 |
|------|------|
| `heroSkillCdReduction = 0.5`（最大） | chargeTime = 6.67s → 每波约 9 次蓄力/英雄；不会过于频繁，因为 5s 自动释放仍是兜底 |
| `heroSkillCdReduction < 0` | 钳位到 0，不允许负值 |
| 战斗暂停中 | 蓄力计时暂停，AUTO_RELEASE_TIMEOUT 计时暂停 |
| 倍速模式 | 蓄力时间受 deltaTime 缩放影响（实际蓄力 = chargeTime / speedMul） |
| 技能蓄满时武将阵亡 | 蓄力进度清零，复活后从 0 重新蓄力 |
| 离线 / 自动防守 | 使用旧 HERO_SKILL_INTERVAL=10s 自动释放，无手动加成 |

### 1.4 WHEN/THEN 验收场景

```
WHEN 战斗开始，武将A蓄力时间=10s
THEN t=10s 时武将A技能能量条蓄满，显示"可释放"提示

WHEN 玩家在 t=10s 点击武将A技能按钮
THEN 技能立即释放
AND 伤害 = heroAtk × 0.5 × 1.5（手动加成）
AND 能量条归零，重新开始 10s 蓄力

WHEN 武将A技能蓄满后 5s 内玩家未操作
THEN t=15s 时技能自动释放
AND 伤害 = heroAtk × 0.5 × 1.0（无加成）

WHEN 3×倍速下武将A蓄力
THEN 蓄力在实际 3.33s 后蓄满（10s / 3）

WHEN 战斗暂停中武将A正在蓄力
THEN 蓄力计时器冻结，恢复后继续
```

### 1.5 配置输出

```javascript
// 新增到 TD_CONSTANTS
SKILL_CHARGE: {
  BASE_CHARGE_TIME: 10,      // 秒
  MANUAL_SKILL_BONUS: 1.5,   // 手动释放伤害倍率
  AUTO_RELEASE_TIMEOUT: 5,   // 蓄满后自动释放等待时间（秒）
  MAX_CD_REDUCTION: 0.5      // 冷却缩减上限
}
```

## 2. 紧急技能（US-A3）

### 2.1 体验目标

> 每关可用 **1-2 次**（每种技能），辅助防御但不能替代正常塔防体系。

### 2.2 技能数值表

| 技能 | 三国名 | 效果类型 | 效果值 | 持续时间 | 冷却时间 | 容许偏差 |
|------|--------|---------|--------|---------|---------|---------|
| **箭雨覆盖** | 万箭齐发 | 对全屏敌人造成固定伤害 | `floor(baseHp(wave) × 0.25)` | 瞬时 | **75s** | ±2s CD |
| **全军冲锋** | 擂鼓助威 | 所有塔和武将攻速提升 | **×1.5 攻速** | **8s** | **75s** | ±10% AS |
| **铜墙铁壁** | 金城汤池 | 所有墙体无敌 + 城主府回血 | 无敌 + 回复城主府 **15% 最大HP** | **5s** | **75s** | ±1s 持续 |

### 2.3 公式与推导

#### 箭雨覆盖伤害

```
arrowRainDamage(wave) = floor(baseHp(wave) × ARROW_RAIN_HP_RATIO)
```

| 参数 | 值 | 推导 |
|------|-----|------|
| `ARROW_RAIN_HP_RATIO` | 0.25 | 对普通兵（hpMul=1.0）造成 25% HP 伤害；对 Boss（hpMul=5×）仅 5%。确保"辅助但不替代" |

**各波次伤害样本**：

| 波次 | baseHp | 箭雨伤害 | vs 黄巾兵(0.8×HP) | vs Boss(5×HP) |
|------|--------|---------|-------------------|--------------|
| 1 | 100 | 25 | 31% | 5% |
| 5 | 157 | 39 | 31% | 5% |
| 10 | 277 | 69 | 31% | 5% |
| 15 | 562 | 140 | 31% | 5% |
| 20 | 1,119 | 279 | 31% | 5% |

**推导逻辑**：
- 25% 对普通兵伤害显著但不致命（需 4 次才能清零）→ 辅助，不替代
- 对 Boss 仅 5% → Boss 战不能靠箭雨
- 每关 75s CD，典型 1-波关（~75s 总时长）只能用 1 次 ✅
- 典型 2-波关（~150s）可用 2 次 → 满足"每关 1-2 次"

#### 全军冲锋效果

```
effectiveAttackSpeed = baseAttackSpeed × CHARGE_ASPD_MULTIPLIER  // 持续 CHARGE_DURATION 秒
```

| 参数 | 值 | 推导 |
|------|-----|------|
| `CHARGE_ASPD_MULTIPLIER` | 1.5 | 8s 内额外产生 50% DPS。对 500 DPS 的队伍 = 额外 2,000 总伤害 |
| `CHARGE_DURATION` | 8 | 8s ≈ 波次 13% 时长，足够清一波小兵群或对 Boss 打出显著伤害 |

**破坏平衡检查**：
- 全队 DPS 假设 500（进化期），8s × 500 × 0.5 = 额外 2,000 伤害
- vs Wave 20 Boss HP(5,595) = 35.7% → 强但不致命
- vs 整波 Wave 20 总 HP(~14,000) = 14.3% → 明显帮助但不能替代防御 ✅

#### 铜墙铁壁

| 参数 | 值 | 推导 |
|------|-----|------|
| `IRON_WALL_DURATION` | 5 | 5s 无敌足够抵挡攻城车/冲城锤 1-2 次攻击，争取反应时间 |
| `TOWNHALL_HEAL_RATIO` | 0.15 | 城主府回复 15% 最大 HP。安全网但不能无限续命 |

#### 冷却时间

所有技能统一 **75s CD**，推导：
- 最短关卡（1波 + 准备）≈ 75s → 每种技能最多用 1 次
- 最长关卡（3波 + 准备）≈ 225s → 每种技能最多用 3 次
- 取中间值：典型 2 波关可用 1-2 次 ✅
- **每关重置**：进入新关卡时所有紧急技能 CD 归零

### 2.4 "仅靠紧急技能不能通关" 验证

假设玩家不放任何塔，仅依赖 3 个紧急技能（75s CD）：
- Wave 10：总敌人 HP ≈ 2,770（4 敌 × 277 × 各倍率 + Boss）
- 箭雨 = 69 × ~4 敌 = 276 伤害（10% 总 HP）
- 冲锋 = 无塔无效果 = 0
- 铁壁 = 纯防御 = 0 伤害
- **结论**：不放塔时 3 技能仅造成约 10% 总 HP 伤害 → **完全不能通关** ✅

### 2.5 边界行为

| 场景 | 行为 |
|------|------|
| 倍速模式 | CD 倒计时受 deltaTime 缩放（3× 速度下实际 75/3=25s 冷却） |
| 暂停中 | CD 计时暂停 |
| 场上无敌人时使用箭雨 | 允许使用，伤害为 0，CD 正常消耗（玩家误操作的自然惩罚） |
| 无墙时使用铜墙铁壁 | 仅城主府回血生效，无敌无目标 |
| CD 中点击按钮 | 按钮灰显，点击无反应 |

### 2.6 WHEN/THEN 验收场景

```
WHEN 玩家在 Wave 10（baseHp=277）释放"箭雨覆盖"
THEN 全屏所有敌人各受到 69 点伤害（floor(277×0.25)）
AND 技能按钮进入 75s 冷却倒计时

WHEN 玩家释放"全军冲锋"
THEN 所有塔和武将攻速变为原来的 1.5× 持续 8s
AND 8s 后恢复正常攻速

WHEN 玩家释放"铜墙铁壁"且城主府当前 HP=400/1000
THEN 所有墙体 5s 内受到的伤害为 0
AND 城主府 HP 回复至 550（400 + 150 = 400 + 1000×0.15）

WHEN 进入新关卡（不论上关紧急技能是否在 CD 中）
THEN 三个紧急技能全部可用（CD 归零）

WHEN 不建造任何塔、不部署武将，仅使用紧急技能挑战 Wave 5
THEN 无法通关（敌人 HP 总量远超紧急技能总伤害）
```

## 3. 体力系统（US-B1）

### 3.1 体验目标

> 日活玩家每天可玩 **10-15 次**；重度玩家通过分散登录可玩 **20+** 次。

### 3.2 核心参数

| 参数 | 值 | 推导 |
|------|-----|------|
| `STAMINA_MAX` | **12** | PRD 建议 12-15；取 12 使单次登录恰好 ~12 局，匹配"10-15 次"目标低端 |
| `STAMINA_COST_NORMAL` | **1** | 每关 1 点，简洁清晰 |
| `STAMINA_COST_PRACTICE` | **0** | 练习模式免费（见 §4） |
| `STAMINA_RECOVER_INTERVAL` | **25 分钟** | PRD 建议 20-30 分钟；取 25 分钟平衡恢复速度 |
| `STAMINA_RECOVER_AMOUNT` | **1** | 每次恢复 1 点 |

### 3.3 日玩次数推算

| 玩家类型 | 行为模式 | 日玩次数 | 说明 |
|---------|---------|---------|------|
| 轻度（1 次登录） | 消耗满体力 12 点 | **12** | 游戏时间 ~24 min（12×2min/关） |
| 日活（2 次登录，间隔 8h） | 12 + min(12, floor(480/25)) = 12 + 12 | **24** | 但第二次未必全消耗 → 实际 ~15-20 |
| 重度（3 次登录，间隔 5h） | 12 + 12 + 12 = 36 | **≤36** | 理论上限，实际偏低因不会完美消耗 |
| 离线 24h 回归 | min(12, floor(1440/25)) = 12 | **12** | 离线恢复上限为 STAMINA_MAX |

**目标匹配**：日活玩家 15-20 次/天 → PRD 目标 10-15 的宽松达成 ✅

### 3.4 离线补偿公式

```
offlineRecovery = min(STAMINA_MAX - currentStamina, floor(offlineMinutes / STAMINA_RECOVER_INTERVAL))
newStamina = currentStamina + offlineRecovery
```

- 最大不超过 `STAMINA_MAX`
- `offlineMinutes` 取 `Date.now() - lastSaveTimestamp`（毫秒转分钟）

### 3.5 边界行为

| 场景 | 行为 |
|------|------|
| 体力已满（12/12） | 恢复计时器暂停，不浪费；显示"体力已满" |
| 体力为 0 | 显示"体力不足，N 分钟后恢复 1 点"；"开始战斗"按钮灰显 |
| 战斗失败 | 已消耗的 1 点体力**不退还**（激励认真对待每关） |
| 战斗胜利 | 体力不额外返还 |
| 离线超过 5 小时（12×25min=300min） | 恢复到满 12 点 |
| 旧存档（无 stamina 字段） | 迁移时初始化为 STAMINA_MAX（满体力），废弃 DAILY_CHALLENGE_LIMIT |
| 自动防守（离线/后台挂机） | **不消耗体力**（仅手动挑战消耗） |

### 3.6 每日可玩时长验算

```
日玩次数(casual) = 12 局 × 2 min/局 = 24 分钟
日玩次数(active) = 20 局 × 2 min/局 = 40 分钟
```

PRD §1.5 KPI 目标："每日可玩时长 20-40 分钟" → 完美匹配 ✅

### 3.7 WHEN/THEN 验收场景

```
WHEN 玩家当前体力=12/12，点击关卡"开始战斗"
THEN 体力扣减为 11/12，正常进入战斗

WHEN 玩家当前体力=0/12，点击"开始战斗"
THEN 弹出提示"体力不足，N分钟后恢复1点"，按钮灰显

WHEN 玩家体力=5/12，离线 3 小时后上线
THEN 体力 = min(12, 5 + floor(180/25)) = min(12, 5+7) = 12

WHEN 玩家体力=10/12，离线 30 分钟后上线
THEN 体力 = min(12, 10 + floor(30/25)) = min(12, 10+1) = 11

WHEN 加载旧存档（无 stamina 字段）
THEN stamina 初始化为 12，恢复计时器从当前时间开始
```

### 3.8 配置输出

```javascript
// 新增到 TD_CONSTANTS
STAMINA: {
  MAX: 12,
  COST_NORMAL: 1,
  COST_PRACTICE: 0,
  RECOVER_INTERVAL: 25,   // 分钟
  RECOVER_AMOUNT: 1
}
```

## 4. 练习模式奖励（US-B2）

### 4.1 体验目标

> 有少量奖励但 **不会成为刷资源最优路径**。

### 4.2 参数

| 参数 | 值 | 推导 |
|------|-----|------|
| `PRACTICE_REWARD_RATIO` | **0.25** | PRD 建议 20-30%；取 25%（中值）|
| 练习模式装备掉落 | **禁止** | 设为 0%（正常模式才掉装备） |
| 练习模式玉石掉落 | **禁止** | 设为 0% |

### 4.3 经济验证

```
正常模式效率 = 金币奖励 × 1.0 / 1 体力 = goldReward per stamina
练习模式效率 = 金币奖励 × 0.25 / 0 体力 = 无限（按时间衡量）
```

| 关卡 | 正常金币 | 练习金币(25%) | 正常 gold/min | 练习 gold/min |
|------|---------|-------------|-------------|-------------|
| 1-1 (Wave 1) | 50 | 12 | 25 | 6 |
| 2-4 (Wave 9,10) | 1,027 | 256 | 342 | 85 |
| 5-5 (Wave 20) | 3,555 | 888 | 1,185 | 296 |

**时间效率对比**：练习模式 gold/min 仅为正常模式的 25%。即使无限刷练习模式，时间效率远低于等体力恢复后打正常模式（25% vs 100%）。**不会成为最优路径** ✅

**极端情况**：玩家 24 小时不停刷最高关练习模式：
- 296 gold/min × 1440 min = 426,240 gold
- vs 正常模式（~24 局 × 3,555）= 85,320 gold
- 练习模式总量高但需要连续 24h 在线操作，实际不可行

### 4.4 WHEN/THEN 验收场景

```
WHEN 玩家选择已通关的 2-4 关卡，点击"练习"
THEN 不消耗体力，正常进入战斗

WHEN 练习模式通关
THEN 获得正常奖励的 25%（金币、经验均按比例）
AND 不获得任何装备或玉石掉落
AND 不更新星级评价、不推进关卡进度

WHEN 反复刷练习模式
THEN 每次奖励不递减（固定 25%），无次数限制
```

### 4.5 配置输出

```javascript
// 新增到 TD_CONSTANTS
PRACTICE: {
  REWARD_RATIO: 0.25,      // 金币、经验的倍率
  EQUIP_DROP: false,        // 禁止装备掉落
  JADE_DROP: false,         // 禁止玉石掉落
  PROGRESS_UPDATE: false    // 不更新星级/进度
}
```

## 5. 飘字合并（US-C1）

### 5.1 体验目标

> 高攻速塔（连弩塔 AS=3.0）不造成视觉轰炸；同屏飘字数量可控。

### 5.2 参数

| 参数 | 值 | 推导 |
|------|-----|------|
| `DAMAGE_TEXT_MERGE_WINDOW` | **0.3s** | 连弩塔 AS=3.0 → 攻击间隔 0.33s。0.3s 窗口恰好把连续两发合并为一次飘字 |
| `DAMAGE_TEXT_MAX_ONSCREEN` | **15** | 经验值：>15 个飘字人眼难以追踪；进化诸葛连弩(AS=4.0, multi_4)最坏=4 飘字/0.25s = 16/s，15上限可控 |
| `DAMAGE_TEXT_DURATION` | **0.8s** | 飘字从出现到完全淡出的时间 |
| `DAMAGE_TEXT_FLOAT_DISTANCE` | **30px** | 向上漂浮距离 |
| `DAMAGE_TEXT_RANDOM_OFFSET` | **±8px** | 水平随机偏移，防止重叠 |

### 5.3 合并逻辑

```
IF 同一攻击源(towerUid) 对同一目标(enemyUid) 在 MERGE_WINDOW 内再次命中
THEN 累加伤害到当前飘字，不创建新飘字
     更新飘字文本为累加值
     重置飘字淡出计时器
```

### 5.4 最坏情况验证

| 场景 | 产生频率 | 同屏飘字估算 | 结果 |
|------|---------|-------------|------|
| 6 座 Lv5 连弩塔（AS=3.0）攻击同区域 | 每 0.33s × 6 = 18/s（合并前） | 合并后 ~9/s（0.3s窗口），存活0.8s → ~7 同屏 | ✅ <15 |
| 6 座进化诸葛连弩（AS=4.0, multi_4）| 每 0.25s × 6 × 4目标 = 96/s（合并前） | 合并后 ~6/s per tower × 6 = ~36 → 上限 15 | ✅ 裁剪生效 |
| 单个慢速投石车 | 每 4s 一次 | 1 飘字（可能溅射几个） | ✅ 清晰可读 |

### 5.5 WHEN/THEN 验收场景

```
WHEN 连弩塔（AS=3.0）连续攻击同一敌人
THEN 每 0.3s 内的多次命中合并为一个飘字
AND 飘字显示合并后的总伤害值（如 "45" 而非两次 "15" + "15" + "15"）

WHEN 50个实体同屏且飘字频繁触发
THEN 同屏飘字数量不超过 15 个
AND 超出时复用最早的飘字对象

WHEN 投石车（AS=0.25）命中 1 个目标
THEN 显示单独飘字，不进行合并
```

## 6. 连杀阈值（US-C2）

### 6.1 体验目标

> 连杀提示频率适中，**每波 1-3 次**触发有效连杀提示。

### 6.2 参数

| 参数 | 值 | 推导 |
|------|-----|------|
| `KILL_STREAK_WINDOW` | **4s** | PRD 建议 3-5s；取 4s。模拟验证：5 敌/波 → ~1.2 次触发；7 敌/波 → ~2.1 次 |
| 阈值级别 | 见下表 | |

### 6.3 连杀等级表

| 连杀数 | 等级 | 提示文字 | 颜色 | 字号 | 特效 | 金币加成 |
|--------|------|---------|------|------|------|---------|
| 2 | 双杀 | "双杀！" | 白色 | 24px | 弹出 | +5% |
| 3 | 三连 | "三连杀！" | 黄色 | 28px | 弹出 + 轻微放大 | +10% |
| 5 | 五连 | "五连绝杀！" | 橙色 | 32px | 屏幕轻微闪光 | +15% |
| 8 | 杀神 | "杀神降临！" | 红色 | 36px | 全屏震动 + 闪光 | +20% |
| 12+ | 万夫 | "万夫莫敌！" | 金色 | 40px | 长持续 + 全屏金光 | +30% |

### 6.4 金币加成公式

```
streakGoldBonus = 击杀该敌人的基础金币 × STREAK_BONUS_TABLE[streakLevel]
```

- 加成仅应用于**触发该等级时击杀的那个敌人**的金币奖励
- 不追溯应用于之前击杀的敌人

**经济影响验证**：
- Wave 10 有 ~5-8 敌人，假设触发 1-2 次三连杀（+10%）
- 每敌击杀金币 ≈ 875/5 = 175g，加成 = 175 × 0.10 = 17.5g
- 全波加成总量 ≈ 35-70g / 875g = 4-8% → 微量奖励，不影响经济平衡 ✅

### 6.5 连杀重置

```
IF timeSinceLastKill > KILL_STREAK_WINDOW
THEN killStreakCount = 0
```

### 6.6 边界行为

| 场景 | 行为 |
|------|------|
| 同一帧内多个敌人死亡 | 全部计入连杀（视为同一时刻） |
| 连杀数 > 12 | 保持"万夫莫敌"等级，不再升级；金币加成维持 +30% |
| 波次结束时有活跃连杀 | 连杀中断；波次结算显示本波最高连杀数 |
| Boss 被击杀算入连杀 | 是，Boss 击杀也计入连杀计数 |
| 倍速模式 | KILL_STREAK_WINDOW 受 deltaTime 缩放（3× 下实际 4/3=1.33s 窗口） |

### 6.7 频率验证（蒙特卡洛模拟 N=1000）

基于随机击杀时序的保守下界估计（实际 TD 中敌人聚集效应会使频率更高）：

| 波次敌人数 | 60s 波次 | 平均触发次数 | 平均最高连杀 |
|-----------|---------|------------|------------|
| 3 | 60s | 0.4 | 1.4 |
| 5 | 60s | 1.2 | 2.0 |
| 7 | 60s | 2.1 | 2.6 |
| 10 | 60s | 3.9 | 3.6 |

考虑敌人在实际 TD 中成群经过扼杀区域的聚集效应，实际频率约为模拟值的 1.5-2×。结论：5+ 敌人的波次中，连杀触发 1-3 次 ✅

### 6.8 WHEN/THEN 验收场景

```
WHEN 玩家在 4s 内连续击杀 2 个敌人
THEN 屏幕中央弹出白色"双杀！"
AND 第 2 个敌人的击杀金币获得 +5% 加成

WHEN 连杀计数到达 5（4s 窗口内）
THEN 显示橙色"五连绝杀！"+ 屏幕闪光
AND 该敌人击杀金币 +15%

WHEN 最后一次击杀后超过 4s 无新击杀
THEN 连杀计数归零

WHEN 3× 倍速下 2 敌在实际 1s 内被击杀（游戏时间 3s）
THEN 连杀仍然有效（4s 游戏时间窗口内）

WHEN 波次结束
THEN 结算面板显示本波最高连杀数
```

## 8. 武将羁绊加成（US-E2）

### 8.1 体验目标

> 加成明显（约 **10-15% 有效战力提升**）但不至于"不用羁绊就过不了关"。

### 8.2 设计约束

- `MAX_ASSIGNED_HEROES = 3`：最多部署 3 名武将
- 大部分羁绊需要 2-3 人，填满 3 个槽位
- 多羁绊叠加理论可能但受限于 3 个槽位
- 羁绊加成与武将等级加成**乘法叠加**（不是加法）

### 8.3 羁绊数值表

| # | 羁绊名称 | 武将组合 | 所需人数 | 加成类型 | 加成数值 | 加成目标 |
|---|---------|---------|---------|---------|---------|---------|
| 1 | **桃园结义** | 刘备+关羽+张飞 | 3/3 | 攻防+CD | ATK **+15%**, DEF **+15%**, 技能 CD **-20%** | 仅三人自身 |
| 2 | **卧龙凤雏** | 诸葛亮+庞统 | 2/2 | 全局增伤 | 全场塔 ATK **+10%**, 技能范围 **+20%** | 全场塔+武将 |
| 3 | **五虎上将** | 关羽+张飞+赵云+马超+黄忠（任意3） | 3/5 | 攻速 | 全体武将 ASPD **+25%** | 所有已部署武将 |
| 4 | **虎豹骑** | 曹操+夏侯惇 | 2/2 | 攻防 | 全场塔 ATK **+8%**, 全墙体 HP **+20%** | 全场塔+墙 |
| 5 | **江东双璧** | 周瑜+孙策 | 2/2 | 火属性 | 火属性伤害（火油塔/火油池）**+30%** | 指定塔类型 |

### 8.4 叠加关系

```
最终属性 = 基础属性 × 等级加成倍率 × 羁绊加成倍率
```

**示例**：关羽 Lv20 ATK 基础=100，等级加成 ×1.5，桃园结义 ×1.15
```
最终 ATK = 100 × 1.5 × 1.15 = 172.5
若仅等级加成（无羁绊）：100 × 1.5 = 150
羁绊额外贡献 = 172.5 - 150 = 22.5（+15%）
```

### 8.5 有效战力提升估算

| 羁绊 | 填充槽位 | 估算全队战力提升 | 推导 |
|------|---------|---------------|------|
| 桃园结义 | 3/3 | ~8-12% | 3 武将占全队约 30% DPS；+15% ATK 提升 → 30%×15% = 4.5% DPS + CD 减少额外 ~4% |
| 卧龙凤雏 | 2/3 | ~10-12% | 全场塔 +10% ATK 直接提升 ~10% 总 DPS |
| 五虎上将 | 3/3 | ~7-10% | 武将 ASPD +25% → 武将 DPS +25%；武将占 30% → +7.5% 总 DPS |
| 虎豹骑 | 2/3 | ~8-10% | 塔 ATK +8% ≈ +8% 塔 DPS + 墙 HP 延长存活 ~10% |
| 江东双璧 | 2/3 | ~5-8% | 仅火属性塔受益；若队伍含 2 火油塔，+30% 火伤 ≈ +5% 全队 |

**结论**：所有羁绊提升在 5-12% 范围，显著但非必须 ✅

### 8.6 激活条件

| 规则 | 说明 |
|------|------|
| 同时存活 | 组合中的武将必须**全部存活**且**在场**才激活 |
| 成员阵亡 | 任一成员 HP 归零撤退 → 羁绊**临时解除** |
| 成员复活 | 武将复活回场后 → 自动重新检测并激活 |
| 多羁绊叠加 | 若部署的 3 人同时满足多个羁绊 → 全部生效（乘法叠加） |

**多羁绊可行性验证**（3 槽位）：

| 组合 | 可激活羁绊 | 总提升 |
|------|-----------|-------|
| 刘备+关羽+张飞 | 桃园结义 + 五虎上将(2/3 不够) | 仅桃园 ~10% |
| 关羽+张飞+赵云 | 五虎上将 (3/5) ✅ | ~8% |
| 诸葛亮+庞统+赵云 | 卧龙凤雏 ✅ | ~11% |
| 曹操+夏侯惇+任意 | 虎豹骑 ✅ | ~9% |
| 周瑜+孙策+任意 | 江东双璧 ✅ | ~6% |

不存在 3 人组合能叠加 2 个羁绊的情况（桃园需要 3 人全占满，五虎需 3/5 但和桃园共享关羽+张飞只有 2/5），这是预期的设计：**每次部署只能激活 1 个羁绊**，选择哪个是策略决策。

### 8.7 边界行为

| 自动防守（离线） | 羁绊默认激活（不检查存活状态） |

## 9. Boss 专属技能数值（US-E3）

### 9.1 体验目标

> 每个 Boss 有独特机制需要针对性应对。Boss HP/ATK 比当前 ×3/×2 **更细致地区分角色定位**。

### 9.2 Boss 基础属性倍率表

### 9.4 Boss 专属技能详细数值

#### 9.4.1 张角 — 召唤术

| 参数 | 值 | 推导 |
|------|-----|------|
| 召唤间隔 | **15s** | 60s 波次中召唤约 3-4 次 |
| 每次召唤数 | **2** 个黄巾兵 | 每次增加小量压力 |
| 召唤兵 HP | `baseHp(wave) × 0.5` | Wave 5: 78 HP → Lv1 箭塔 2 发可杀 |
| 召唤兵 ATK | `baseAtk(wave) × 0.5` | Wave 5: 10 ATK → 对墙威胁低 |
| 召唤上限 | **6** 同时存活 | 防止无限堆积 |
| 召唤兵类型 | `td_militia` | 最弱兵种，范围 AOE 轻松清理 |

**压力验证**：
- 60s 内召唤 4 次 × 2 = 8 个小兵（上限 6 同存）
- 额外总 HP = 8 × 78 = 624 → 约等于张角自身 HP
- 相当于 Boss 有效 HP 翻倍（需同时处理 Boss + 小兵）
- 但一座箭雨塔/投石车可高效清理 → 有反制方案 ✅

#### 9.4.2 吕布 — 冲锋

| 参数 | 值 | 推导 |
|------|-----|------|
| 冲锋间隔 | **20s** | 60s 内约 2-3 次 |
| 冲锋伤害 | `bossAtk × 3` | Wave 10: 87×3 = 261 → 可摧毁木栅栏(200HP) |
| 冲锋范围 | 前方直线 **3 格** | 穿过 1-2 个建筑/墙体 |
| 无视墙体 | 冲锋时**忽略第 1 道墙**（穿过但不破坏） | 必须多层防御 |
| 冲锋后停顿 | **2s**（眩晕自身） | 冲锋后有 DPS 窗口 |

**应对验证**：
- 木栅栏 HP=200 → 1 次冲锋摧毁 (261>200) → 单层墙不够
- 城墙 HP=500 → 1 次冲锋不摧毁(261<500) → 城墙可挡但仍会穿过第 1 道
- 铁壁 HP=1200 → 安全挡住
- 多层墙体 + 减速陷阱 = 有效反制 ✅

#### 9.4.3 曹操 — 鼓舞

| 参数 | 值 | 推导 |
|------|-----|------|
| 鼓舞范围 | **3 格**半径 | 覆盖周围敌人但不是全图 |
| ATK 加成 | **+40%** | 使普通兵攻墙效率大幅提升 |
| 速度加成 | **+20%** | 加速推进但不夸张 |
| 持续类型 | **光环（持续）** | 曹操存活即生效 |
| 失效条件 | 曹操被击杀 | 立即移除所有 buff |

**应对验证**：
- 优先击杀策略：曹操 HP=2,810，团队 DPS~350 → ~8s 集火杀死 → buff 消失 ✅
- 分离策略：用减速/墙体将曹操与部队拉开距离 → buff 范围外的敌人不受益 ✅
- 不理会曹操：普通兵 ATK×1.4 → 墙体存活时间减少 29% → 明显但不致命 ✅

#### 9.4.4 关羽 — 无双斩

| 参数 | 值 | 推导 |
|------|-----|------|
| 斩击间隔 | **12s** | 60s 内约 4-5 次 |
| 斩击角度 | 前方 **120°** 扇形 | 接近正面半圆 |
| 斩击范围 | **2 格** 半径 | 覆盖 ~3×3 区域内的建筑 |
| 对敌人伤害 | 0（不伤友军） | — |
| 对建筑伤害 | `bossAtk × 3` | Wave 19: 148×3 = 444 → 可摧毁城墙(500HP 差一点) |
| 对建筑最大 HP% | **30%** | 无论 ATK 多高，单次最多扣建筑 30% 最大 HP |

**推导**：引入 30% 上限防止进化塔被一击秒杀（进化塔无 HP 但城墙有）。

**应对验证**：
- 集中布局：3 座塔挤在一起 → 一次无双斩伤 3 座 → 灾难性
- 分散布局：塔间距 ≥2 格 → 单次斩击最多命中 1-2 座 → 可控 ✅
- 关羽 HP=4,880 → 需要约 10-14s 集火 → 会施放 1-2 次无双斩 → 可承受

#### 9.4.5 司马懿 — 分身术

| 参数 | 值 | 推导 |
|------|-----|------|
| 分身间隔 | **30s** | 60s 波次中最多 2 次分身 |
| 分身数量 | **2** 个 | 总共 3 个实体（1 本体 + 2 分身） |
| 分身 HP | 本体 HP × **40%** | 5,595 × 0.4 = 2,238 HP 每个分身 |
| 分身 ATK | 本体 ATK × **60%** | 有一定威胁但低于本体 |
| 分身使用技能 | **否** | 分身不会再分身 |
| 分身死亡 | 消散动画，不掉落奖励 | — |
| 本体死亡 | **所有分身立即消散**，Boss 击杀完成 | 核心机制 |
| 辨别机制 | 无烽火台/天眼台 → 三个外观完全相同 | 需要侦测能力 |
| 侦测效果 | 有侦测 → 本体头顶显示标记 | 天眼台优势场景 |
| 分身被杀后 | 下次分身间隔到达时重新创建 | 持续压力 |

**有效 HP 验证**：
- 无侦测（盲打）：玩家随机集火 → 期望击杀本体前要消灭平均 1-2 个分身
  - 有效 HP = 5,595 + 1.5 × 2,238 = 8,952 → 比面板 HP 多约 60%
- 有侦测（精准打）：直接集火本体 → 有效 HP = 5,595
  - 天眼台带来的 HP 等效减免 = **37%** → 非常值得投资 ✅

## 10. 速度倍率（US-A2）

### 10.1 体验目标

### 10.2 参数

| `SPEED_2X` | **2.0** | 中速 |

### 10.3 影响范围

deltaTime 缩放应用于所有游戏逻辑时钟：

| 受影响 | 不受影响 |
|--------|---------|
| 敌人移动速度 | UI 动画（按钮、面板过渡） |
| 塔攻击间隔 | 飘字浮动动画（保持可读性） |
| 技能蓄力计时 | 玩家输入响应 |
| 紧急技能冷却 | 暂停/恢复逻辑 |
| 波次间准备倒计时 | — |
| Boss 技能间隔 | — |
| 灼烧/减速持续时间 | — |
| 连杀时间窗口 | — |

### 10.4 体验验证

| 速度 | 60s 波次实际时长 | 体感 | 备注 |
|------|----------------|------|------|
| 1× | 60s | 正常节奏 | 新手 / Boss 关推荐 |
| 2× | 30s | 快但清晰 | 日常刷关推荐 |
| 3× | 20s | 很快，需要预判 | 高手 / 练习模式 |

- **3× 下关键事件可读性**：Boss 技能预告 1.5s → 实际 0.5s，仍足以让玩家看到动画并做出反应
- **3× 下手动技能操作**：蓄力 10s → 实际 3.3s，自动释放窗口 5s → 实际 1.67s → 操作更紧凑但可行

### 10.5 边界行为

| 场景 | 行为 |
|------|------|
| 暂停中切换速度 | 允许，恢复后以新速度运行 |
| 退出防守模式后重进 | 速度重置为 1× |
| 切换速度的瞬间 | 立即生效，无过渡 |
| deltaTime 极端值（帧率骤降） | 钳位 `scaledDelta = min(deltaTime × speedMul, 0.1)` 防止物理跳跃 |

### 10.6 WHEN/THEN 验收场景

```
WHEN 玩家点击速度按钮，当前为 1×
THEN 切换到 2×，按钮显示"2×"
AND 所有敌人移动速度视觉上翻倍

WHEN 切换到 3×，波次剩余 30s（游戏时间）
THEN 实际约 10s 后波次结束

WHEN 3× 速度下武将技能蓄满
THEN 自动释放倒计时为实际 1.67s（5s/3）
AND 飘字浮动动画保持正常速度（不加速）

WHEN 退出防守模式并重新进入
THEN 速度重置为 1×

WHEN 帧率降至 10FPS（deltaTime=0.1s），3× 速度
THEN scaledDelta = min(0.1×3, 0.1) = 0.1（钳位保护）
```

### 11.1 体力 vs 日活时长

### 11.2 进化 DPS vs Boss HP

| Boss | BossHP | 预期团队DPS（进化期） | 击杀时间 | 波次时长 | 余量 |
|------|--------|---------------------|---------|---------|------|
| 张角 | 628 | ~100 | 6.3s | 60s | 54s ✅ |
| 吕布 | 1,662 | ~200 | 8.3s | 60s | 52s ✅ |
| 曹操 | 2,810 | ~350 | 8.0s | 60s | 52s ✅ |
| 关羽 | 4,880 | ~500 | 9.8s | 60s | 50s ✅ |
| 司马懿 | 5,595(+分身) | ~500 | 11.2-18s | 60s | 42-49s ✅ |

结论：所有 Boss 在进化塔配置下可在 20s 内击杀，留充足时间处理随波小兵 ✅

### 11.3 紧急技能 vs 正常防御

| 验证项 | 计算 | 结论 |
|--------|------|------|
| 箭雨 vs 总波次 HP | 25% baseHp × 敌人数 / 总波次 HP | 每次覆盖约 20-25% 总 HP → 需 4+ 次才能清波 → 辅助 ✅ |
| 冲锋 vs 总波次 HP | +50% DPS × 8s / 60s 波次 | ≈6.7% 额外波次 DPS → 辅助 ✅ |
| 仅紧急技能（无塔） | 箭雨+冲锋+铁壁 总伤 < 波次 30% HP | 不可能通关 ✅ |

### 11.4 羁绊 vs 无羁绊通关

| 关卡 | 无羁绊预期 DPS | 有羁绊(最佳) DPS | 差异 | 结论 |
|------|--------------|----------------|------|------|
| Ch3 Boss | 350 | 350 × 1.12 = 392 | +12% | Boss 击杀快 1s → 有帮助但不决定性 ✅ |
| Ch5 Boss | 500 | 500 × 1.12 = 560 | +12% | Boss 击杀快 2s → 同上 ✅ |

### 11.5 练习模式不优于正常模式

| 比较 | 正常模式 | 练习模式 |
|------|---------|---------|
| Gold/体力点 | 100% × 奖励 | ∞（0 消耗）但只有 25% |
| Gold/分钟 | 100% × 奖励/2min | 25% × 奖励/2min |
| 时间效率比 | 基准 | **25%** |
| 装备/玉石 | 有 | **无** |

结论：正常模式在所有可量化维度（时间效率、稀有掉落）均显著优于练习模式 ✅

### 11.6 连杀金币加成对经济影响

- 最大连杀加成：+30%，但仅对触发击杀的单个敌人
- 每波最高连杀场景（10 敌全连杀）：0.3 × 1/10 = +3% 波次总金币
- 平均场景（5 敌，1 次三连杀）：+10% × 1/5 = +2% 波次总金币
- **结论**：连杀金币加成对经济影响 <5%，纯激励意义 ✅

### 11.7 3× 速度下关键操作窗口

| 操作 | 1× 窗口 | 3× 窗口 | 可行? |
|------|---------|---------|------|
| 手动技能释放 | 5s | 1.67s | ✅ 紧凑但够用 |
| Boss 技能预告 | 1.5s | 0.5s | ⚠️ 勉强 |
| 紧急技能决策 | 随时 | 随时 | ✅ |
| 连杀窗口 | 4s | 1.33s | ✅ 不受影响(游戏时间) |

⚠️ Boss 技能预告在 3× 下仅 0.5s，可能偏短但仍可感知。若测试反馈太快，建议 Boss 预告时间不受倍速影响（固定 1.5s 实际时间）。
