## 1. 概述

### 1.1 问题陈述

当前塔防系统技术实现完整（A\*寻路、12种敌人、13种建筑、Canvas渲染、武将部署），但玩家核心反馈是**"不好玩"**。根因分析（见 `ai-docs/td-fun-analysis.md`）揭示五个结构性问题：

| # | 问题 | 严重度 | 现状 |
|---|------|--------|------|
| 1 | **战斗中零交互** — 点开始后完全观战 | 🔴 致命 | 塔/武将/敌人全自动，玩家无事可做 |
| 2 | **每日3次就完了** — 每天仅3-6分钟内容 | 🔴 致命 | `DAILY_CHALLENGE_LIMIT: 3`，玩家还没熟悉就被限制 |
| 3 | **布阵无趣** — 封路检测阻止迷宫设计 | 🟡 严重 | 所有格子等价，无地形优势，城镇地图非TD专用 |
| 4 | **数值体验平** — 无击杀反馈 | 🟡 严重 | 无飘字伤害、无击杀特效、敌人瞬间消失 |
| 5 | **武将存在感低** — 全自动和塔无区别 | 🟡 严重 | 技能自动释放，无英雄时刻 |

### 1.2 核心玩家价值

> **从"观看"变成"参与"——让玩家在战斗中有事可做、有反馈可看、有策略可想。**

- ⚔ **操作感**：武将技能手动释放 + 全局紧急技能 → 战斗中有决策点
- 🎮 **节奏控制**：加速/暂停 + 体力系统 → 玩家掌控游戏节奏
- 💥 **爽快感**：飘字伤害 + 连杀提示 + 粒子特效 → 击杀即时满足
- 🧠 **策略深度**：半封路迷宫 + 塔进化分支 + 武将羁绊 → 重复可玩性
- 🏆 **英雄时刻**：手动技能加成 + Boss专属机制 + 紧急翻盘技 → 关键时刻的成就感

### 1.3 目标用户

已解锁城防系统的中期玩家（通关 stage_2_10、城主府 ≥ 3），追求策略玩法和操作乐趣。

### 1.4 设计原则

1. **Idle 为基，手操为奖**：自动防守仍是基础，手动操作提供显著加成而非必须
2. **先爽后深**：优先实现感官反馈（飘字/特效），再做策略深度（进化/羁绊）
3. **不改架构**：在现有 Canvas 2D + EventBus + 全局变量架构上增量迭代
4. **与现有系统兼容**：不破坏已有存档、不修改其他游戏系统

### 1.5 成功指标（KPI）

| 指标 | 当前值 | 目标值 | 衡量方式 |
|------|--------|--------|---------|
| 单次战斗中玩家操作次数 | 0（纯观战） | ≥ 5 次/关 | 手动技能释放 + 紧急技能使用的操作计数 |
| 每日可玩时长 | 3-6 分钟 | 20-40 分钟 | 体力系统允许的最大游玩次数 × 单关时长 |
| 战斗中可见反馈事件 | 仅血条变化 | 飘字 + 连杀 + 粒子 + 震屏 | 每次击杀触发的反馈种类数 |
| 布阵有效策略数 | ~1（摆满即可） | ≥ 3 种 | 迷宫路径 / 集火点 / 分散防御等不同策略均可通关 |
| 武将手动操作贡献度 | 0% | 手动释放提供 50% 伤害加成 | 手动 vs 自动技能释放的伤害差 |

## 2. 方向 A：战斗中玩家操作（Phase 1 — 最高优先级）

> 核心目标：让玩家在战斗进行中有有意义的操作可做。

### US-A1：武将技能手动释放

**作为**部署了武将的玩家
**我想要**在武将技能蓄满后手动选择释放时机
**以便于**在关键时刻集中火力，感受到"我的操作改变了战局"

**详细描述**：

当前武将技能每 `HERO_SKILL_INTERVAL (10s)` 自动释放一次，玩家无感。改为"蓄力→手动释放"模式：

- 技能能量条随时间自动蓄满（保留现有 10s 周期作为基础蓄力时间）
- 蓄满后武将头顶显示明显的"技能就绪"提示（发光图标 + 脉冲动画）
- 玩家点击武将头像/技能按钮即可释放
- **手动释放奖励**：手动释放的技能伤害获得额外加成（激励主动操作）
- **自动释放兜底**：蓄满后若超过一定时间未手动释放，则自动释放（无额外加成），保持 Idle 本质
- 技能释放时有清晰的视觉特效（已在 CoC 重制规范中定义）

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 技能蓄力可见 | WHEN 战斗进行中 THEN 每个已部署武将在战场UI上显示技能能量条，能量随时间从0蓄满 |
| 2 | 蓄满提示 | WHEN 武将技能能量蓄满 THEN 武将头像/图标出现明显的"可释放"视觉提示（发光/脉冲），且底部技能按钮高亮 |
| 3 | 手动释放 | WHEN 玩家在技能蓄满后点击对应武将的技能按钮 THEN 立即释放技能，伤害获得额外加成，能量条归零重新蓄力 |
| 4 | 自动兜底 | WHEN 技能蓄满后超过自动释放等待时间且玩家未操作 THEN 自动释放技能（无额外加成），能量条归零 |
| 5 | Idle 兼容 | WHEN 玩家处于自动防守（离线/后台）THEN 武将技能按原有自动节奏释放，不受手动机制影响 |

> 📐 `@numerical-designer`：需要定义——技能蓄力时间（基于武将技能冷却）、手动释放伤害加成倍率、自动释放等待超时时间。

### US-A2：战斗速度控制

**作为**观看战斗的玩家
**我想要**自由切换战斗的播放速度
**以便于**在无聊时加速跳过、在关键时刻放慢观察

**详细描述**：

战斗界面新增速度控制按钮，支持 1×/2×/3× 三档切换。通过修改 `deltaTime` 缩放因子实现（现有 rAF 架构天然支持）。

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 速度按钮可见 | WHEN 进入防守模式且有活跃波次 THEN 战斗界面右上角显示速度切换按钮，显示当前倍速（默认1×） |
| 2 | 三档切换 | WHEN 玩家点击速度按钮 THEN 依次循环切换 1× → 2× → 3× → 1×，按钮显示当前倍速 |
| 3 | 实际加速 | WHEN 切换到 N× 速度 THEN 敌人移动、塔攻击、技能冷却、波次计时均以 N 倍速运行，视觉上可感知加速 |
| 4 | 暂停功能 | WHEN 玩家点击暂停按钮 THEN 战斗所有逻辑暂停（敌人停止移动、塔停止攻击），UI 显示暂停状态 |
| 5 | 暂停中可操作 | WHEN 战斗暂停中 THEN 玩家仍可查看塔信息、规划下一步操作（但不能建造/出售塔） |
| 6 | 恢复继续 | WHEN 暂停状态下点击继续按钮 THEN 战斗以暂停前的速度恢复运行 |
| 7 | 退出重置 | WHEN 退出防守模式再进入 THEN 速度重置为 1× |

### US-A3：全局紧急技能

**作为**面对大波敌人涌入的玩家
**我想要**在关键时刻使用强力全局技能翻盘
**以便于**体验"力挽狂澜"的英雄时刻

**详细描述**：

提供2-3个全局紧急技能（不依赖特定武将），有较长冷却时间，在关键时刻使用。技能从战斗开始时可用，每次使用后进入冷却。每关（非每波）独立冷却。

初始设计的紧急技能：

| 技能 | 三国主题 | 效果概述 | 视觉概述 |
|------|---------|---------|---------|
| **箭雨覆盖** | 万箭齐发 | 对全场敌人造成一次范围伤害 | 屏幕上方落下大量箭矢线条 |
| **全军冲锋** | 擂鼓助威 | 所有塔和武将攻速短暂大幅提升 | 屏幕边缘红色脉冲波 + 所有友方单位闪光 |
| **铜墙铁壁** | 金城汤池 | 所有墙体短暂无敌 + 城主府回复一定HP | 所有墙体金色光罩 + 城主府绿色回复光效 |

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 技能栏可见 | WHEN 战斗进行中 THEN 屏幕底部显示紧急技能栏（2-3个按钮），各自显示图标和冷却状态 |
| 2 | 可使用 | WHEN 紧急技能不在冷却中且玩家点击技能按钮 THEN 立即触发技能效果，播放全屏级视觉特效，进入冷却 |
| 3 | 冷却显示 | WHEN 紧急技能进入冷却 THEN 按钮变灰，显示剩余冷却时间（秒数倒计时），冷却完成后按钮恢复高亮 |
| 4 | 每关独立 | WHEN 开始新关卡 THEN 所有紧急技能冷却重置为可用状态 |
| 5 | 效果可感知 | WHEN 释放"箭雨覆盖" THEN 所有敌人同时受到伤害（HP条明显下降），且屏幕有大面积视觉特效 |
| 6 | 不破坏平衡 | WHEN 仅依赖紧急技能而不布塔 THEN 无法通关（紧急技能是辅助而非替代防御体系） |

> 📐 `@numerical-designer`：需要定义——每个紧急技能的伤害/效果数值、持续时间、冷却时间（建议60-90秒），确保"关键辅助但不替代正常防御"。

### US-A4：战斗中建造/出售松绑

**作为**战斗进行中发现阵型漏洞的玩家
**我想要**在波次间隙和战斗中更自由地调整防御布局
**以便于**实时应对战况变化，体验经典TD"边打边造"的乐趣

**详细描述**：

当前系统已有战斗中建造/出售的基础能力，但限制较多。此US旨在放宽限制，提升体验：

- 波次间的15秒准备时间内：自由建造/出售（售回率保持50%）
- 波次进行中：允许建造新塔（资源够即可），但出售已有塔的售回率降低
- 暂停状态下不可建造/出售（防止暂停规划的零成本策略）

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 准备阶段自由 | WHEN 处于波次间准备阶段（15秒倒计时）THEN 玩家可自由建造和出售塔，出售返还率50% |
| 2 | 战斗中可建造 | WHEN 波次进行中且玩家有足够资源 THEN 玩家可在空闲格子建造新塔，新塔立即开始攻击 |
| 3 | 战斗中出售降低 | WHEN 波次进行中出售塔 THEN 返还率为30%（低于准备阶段的50%） |
| 4 | 建造工具栏常驻 | WHEN 战斗进行中 THEN 底部塔建造工具栏保持可见（非灰显），方便快速建造 |
| 5 | 封路检测仍有效 | WHEN 战斗中建造新塔导致完全封路 THEN 阻止放置，提示"不能完全封锁路径" |

## 3. 方向 B：放宽每日次数限制（Phase 1）

> 核心目标：让玩家想玩就能玩，而非每天3分钟就被拒之门外。

### US-B1：体力系统替代硬次数限制

**作为**想要多玩几局塔防的玩家
**我想要**通过可恢复的体力系统来管理游玩次数
**以便于**按自己的节奏游玩，不被"今天3次用完了"打断

**详细描述**：

将 `DAILY_CHALLENGE_LIMIT: 3` 替换为体力系统：
- 每次进入关卡消耗体力
- 体力按时间自动恢复
- 体力有上限，可以攒一段时间后集中玩
- 目标体验：日活玩家每天可玩10-15次，重度玩家通过时间安排可玩更多

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 体力显示 | WHEN 进入城防界面 THEN 顶部显示当前体力值 / 体力上限，以及下次恢复的倒计时 |
| 2 | 消耗体力 | WHEN 玩家点击"开始波次"且体力 ≥ 单次消耗量 THEN 扣除体力，正常开始战斗 |
| 3 | 体力不足 | WHEN 玩家点击"开始波次"但体力 < 单次消耗量 THEN 弹出提示"体力不足，X分钟后恢复1点"，按钮灰显 |
| 4 | 自动恢复 | WHEN 体力 < 上限 THEN 每隔固定时间自动恢复1点体力（包括离线时间） |
| 5 | 离线补偿 | WHEN 玩家离线后上线 THEN 按离线时长补偿恢复的体力（不超过上限） |
| 6 | 旧存档兼容 | WHEN 加载旧存档（含 DAILY_CHALLENGE_LIMIT 计数）THEN 迁移为体力系统，给予满体力 |

> 📐 `@numerical-designer`：需要定义——体力上限（建议12-15点）、单次消耗量（建议1点/关）、恢复速率（建议每20-30分钟恢复1点）、新关卡/已通关卡的体力消耗差异。

---

### US-B2：已通关卡无限重刷

**作为**想要练习布阵策略或刷取少量资源的玩家
**我想要**无限重复已通关的关卡
**以便于**不受体力限制地磨练技术，同时获得少量回报

**详细描述**：

已通关关卡（星级 ≥ 1）可以不消耗体力地重复挑战，但奖励大幅减少。

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 重刷入口 | WHEN 玩家选择已通关关卡 THEN 显示两个按钮："挑战"（消耗体力，正常奖励）和"练习"（免费，减少奖励） |
| 2 | 免费练习 | WHEN 玩家选择"练习"模式 THEN 不消耗体力，正常进入战斗 |
| 3 | 减少奖励 | WHEN 练习模式通关 THEN 获得正常奖励的一定比例（大幅减少） |
| 4 | 不影响进度 | WHEN 练习模式通关 THEN 不更新星级评价、不推进关卡进度 |
| 5 | 无限次数 | WHEN 玩家连续练习同一关卡 THEN 无次数限制 |

> 📐 `@numerical-designer`：需要定义——练习模式的奖励比例（建议正常奖励的20-30%），确保不会成为刷资源漏洞。

## 4. 方向 C：击杀爽快感（Phase 1）

> 核心目标：让每次击杀都有可见、可感受的反馈，激活多巴胺循环。

### US-C1：飘字伤害数字

**作为**观看战斗的玩家
**我想要**看到每次攻击造成的伤害数字
**以便于**直观感受自己的防御力量，体验数值成长带来的快感

**详细描述**：

塔/武将攻击命中敌人时，在命中位置上方弹出飘字伤害数字，向上浮动后淡出。

- 普通伤害：白色数字
- 暴击伤害（若有）：黄色放大数字 + 抖动效果
- 武将技能伤害：橙色数字 + 较大字号
- 手动释放技能伤害：金色数字 + 更大字号 + 额外发光
- 飘字不应过于密集，高攻速塔（连弩塔）做合并显示（累积一小段时间的伤害合并为一次飘字）

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 普通伤害飘字 | WHEN 塔攻击命中敌人 THEN 在敌人位置上方显示白色伤害数字，向上浮动约1秒后淡出 |
| 2 | 技能伤害飘字 | WHEN 武将技能命中敌人 THEN 显示橙色/金色较大字号伤害数字 |
| 3 | 多目标不混乱 | WHEN 同时有多个飘字 THEN 飘字位置有随机偏移，不完全重叠 |
| 4 | 高攻速合并 | WHEN 连弩塔等高攻速塔连续命中同一目标 THEN 短时间内的多次伤害合并为一次飘字显示 |
| 5 | 性能可控 | WHEN 50个实体同屏且飘字频繁触发 THEN 帧率不低于30FPS（可通过限制同屏最大飘字数实现） |

---

### US-C2：连杀提示系统

**作为**高效消灭敌人的玩家
**我想要**在连续击杀时获得连杀提示
**以便于**感受到自己防御的强大和连续击杀的成就感

**详细描述**：

在短时间窗口内连续击杀敌人时，屏幕中央弹出醒目的连杀提示文字。

- 连杀判定：在时间窗口内的连续击杀数
- 分级提示：不同击杀数对应不同文字和视觉效果
- 提示文字使用三国风格

| 连杀数 | 提示文字 | 视觉效果 |
|--------|---------|---------|
| 2 | 双杀！ | 白色文字弹出 |
| 3 | 三连杀！ | 黄色文字弹出 + 轻微放大 |
| 5 | 五连绝杀！ | 橙色文字 + 屏幕轻微闪光 |
| 8 | 杀神降临！ | 红色文字 + 全屏震动 + 闪光 |
| 12+ | 万夫莫敌！ | 金色文字 + 持续时间更长 |

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 连杀触发 | WHEN 在时间窗口内击杀第2个敌人 THEN 屏幕中央弹出"双杀！"提示文字 |
| 2 | 分级提示 | WHEN 连杀数达到更高阈值 THEN 显示对应级别的提示文字，视觉效果逐级增强 |
| 3 | 连杀重置 | WHEN 超过时间窗口未击杀新敌人 THEN 连杀计数归零 |
| 4 | 不遮挡操作 | WHEN 连杀提示显示 THEN 不遮挡武将技能按钮和紧急技能栏 |
| 5 | 波次结算统计 | WHEN 波次结束 THEN 结算面板显示本波最高连杀数 |

> 📐 `@numerical-designer`：需要定义——连杀时间窗口（建议3-5秒）、各级连杀阈值、连杀是否附带额外奖励加成。

### US-C3：击杀视觉反馈

**作为**看到敌人被消灭的玩家
**我想要**看到丰富的击杀视觉效果
**以便于**获得击杀的即时满足感，而非"敌人突然消失"的空虚感

**详细描述**：

击杀反馈包含三个子系统：

1. **敌人死亡特效**：敌人不再瞬间消失，而是播放死亡动画（倒下/消散/闪烁）
2. **金币飞出粒子**：击杀时从敌人位置弹出金色粒子，飞向屏幕顶部金币计数器
3. **Boss死亡震屏**：Boss被击杀时屏幕短暂震动 + 白色闪光

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 死亡动画 | WHEN 普通敌人HP归零 THEN 播放约0.5秒的死亡动画（闪烁+缩小/消散），而非瞬间消失 |
| 2 | 金币粒子 | WHEN 敌人被击杀 THEN 从敌人位置弹出2-4个金色小粒子（圆形），沿弧线飞向顶部金币显示区域 |
| 3 | Boss震屏 | WHEN Boss敌人HP归零 THEN 屏幕产生短暂震动效果（Canvas位移±3px，持续约0.3秒）+ 短暂白色闪光 |
| 4 | 攻城器械爆炸 | WHEN 攻城器械（攻城车/冲城锤等）被摧毁 THEN 播放较大的破碎/爆炸动画（比普通敌人更夸张） |
| 5 | 性能保护 | WHEN 大量敌人同时死亡 THEN 粒子总数有上限，超出后复用最早的粒子 |

## 5. 方向 D：布阵趣味性（Phase 2）

> 核心目标：让布阵从"摆满就行"变成"我要怎么设计路线"。

### US-D1：半封路机制（允许迷宫设计）

**作为**喜欢策略规划的玩家
**我想要**通过巧妙的塔位布局引导敌人走更长的路线
**以便于**体验经典TD迷宫设计的乐趣，最大化防御塔的攻击时间

**详细描述**：

当前封路检测过于严格——任何可能导致封路的建造都被阻止。改为"半封路"机制：只要存在至少一条从任意生成点到城主府的通路即可（即使该路线很长、很曲折）。

- 鼓励玩家用墙体引导敌人走蛇形路线
- 路径可以很窄（1格宽即可），但不能完全封死
- A\*寻路在每次建造/出售后重新计算最短路径
- 敌人会自动走新的最短路径（建造后看到敌人改道是重要的反馈）

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 允许窄路 | WHEN 玩家建造墙体使通路变窄为1格宽 THEN 允许建造，不弹出封路提示 |
| 2 | 禁止完全封路 | WHEN 玩家建造导致所有生成点到城主府均无路可达 THEN 阻止建造，提示"必须保留至少一条通路" |
| 3 | 路径实时更新 | WHEN 建造新墙体导致最短路径变化 THEN 尚未到达旧路径段的敌人立即重新寻路走新路径 |
| 4 | 路径预览 | WHEN 玩家拖拽墙体到目标位置（放置前）THEN 半透明显示预计的敌人新路径（帮助规划迷宫） |
| 5 | 迷宫长路有效 | WHEN 玩家构建迷宫使敌人路径延长2-3倍 THEN 沿途的防御塔可多次攻击经过的敌人 |

### US-D2：专用TD地图（每章独立）

**作为**每章推进的玩家
**我想要**每章有独特的战场地形布局
**以便于**面对不同的战术挑战，而非每关用相同策略

**详细描述**：

当前TD复用城镇地图，缺乏地形变化。为5章各设计专用TD地图，包含：

- **预设出生点**：固定的敌人入口位置（每章不同数量和方位）
- **瓶颈地形**：天然的窄路、河流、山岩等不可建造区域
- **战略要地**：特别适合放塔的关键位置（地形优势，如高地）
- 地图尺寸保持和城镇地图一致（复用现有Canvas/摄像机系统）

| 章节 | 地图主题 | 地形特色 |
|------|---------|---------|
| 黄巾之乱 | 平原村落 | 简单开阔，1个出生点，适合新手学习 |
| 诸侯讨董 | 虎牢关口 | 天然窄道+两翼包抄路线，2个出生点 |
| 赤壁烽火 | 江岸营寨 | 河流分隔地图，桥梁为必经之路，2个出生点 |
| 荆州争夺 | 城池攻防 | 多层城墙预设，敌人需逐层突破，3个出生点 |
| 决战五丈原 | 连营大阵 | 复杂迷宫式地形，多个出生点四面围攻 |

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 章节绑定 | WHEN 玩家进入第N章的关卡 THEN 加载对应章节的专用TD地图（非城镇地图） |
| 2 | 出生点固定 | WHEN 波次开始 THEN 敌人从该地图预设的出生点生成（不再是随机四边） |
| 3 | 地形可见 | WHEN 玩家查看地图 THEN 不可建造区域（河流/山岩）有明显的视觉标识 |
| 4 | 地形影响策略 | WHEN 玩家面对不同章节地图 THEN 需要根据地形调整阵型（同一套阵型无法通用所有章节） |
| 5 | 兼容现有系统 | WHEN 加载专用地图 THEN 现有的A\*寻路、建造/出售、碰撞检测系统正常工作 |

## 6. 方向 E：质变式升级（Phase 3）

> 核心目标：打破"数值平滑增长"，创造"质变"感和策略深度。

### US-E1：塔进化系统（分支升级）

**作为**将防御塔升到满级的玩家
**我想要**在Lv5之后选择不同的进化路线
**以便于**根据当前关卡需要做出有意义的策略选择

**详细描述**：

塔达到 Lv5（当前最大等级）后，可消耗额外资源进行"进化"，从2条分支中选择1条。进化不可逆，增加策略选择的重量感。

初始进化设计：

| 基础塔 | 进化路线A | 进化路线B |
|--------|----------|----------|
| 箭塔 | **神射塔** — 射程大增、单体伤害极高，优先攻击Boss | **箭雨塔** — 射程不变、变为范围攻击、攻速下降 |
| 弩车台 | **穿甲弩** — 无视目标防御、单体极高伤害 | **连弩车** — 同时攻击3个目标、单体伤害降低 |
| 投石车台 | **烈焰石** — 溅射范围增大、附带持续灼烧 | **震天锤** — 命中目标及周围短暂眩晕（停止移动） |
| 火油塔 | **天火塔** — 灼烧伤害大幅提升、范围增大 | **毒烟塔** — 范围内敌人持续减速+减防 |
| 连弩塔 | **诸葛连弩** — 攻速翻倍、同时攻击4目标 | **破阵弩** — 攻速降低，但每次攻击穿透一排敌人 |
| 烽火台 | **天眼台** — 侦测范围翻倍、全场友军攻击加成提升 | **号令台** — 范围内友军攻速加成、武将技能冷却加速 |

**验收标准**：

| # | 标准 | WHEN / THEN |
|---|------|-------------|
| 1 | 进化入口 | WHEN 玩家点击Lv5满级塔 THEN 塔信息面板新增"进化"按钮，显示2条进化路线的预览（名称+效果简述） |
| 2 | 选择进化 | WHEN 玩家选择一条进化路线且资源足够 THEN 消耗资源，塔外观变化，属性按进化路线更新 |
| 3 | 不可逆 | WHEN 塔已进化 THEN 无法切换到另一条路线，面板显示已选路线标记 |
| 4 | 视觉区分 | WHEN 塔完成进化 THEN 塔的Canvas渲染外观有明显变化（颜色/形状/特效），玩家一眼可分辨进化类型 |
| 5 | 功能生效 | WHEN 神射塔攻击 THEN 射程和伤害按进化属性计算（而非Lv5属性） |
| 6 | 出售处理 | WHEN 出售已进化的塔 THEN 返还包含进化费用的部分（按出售比例） |

> 📐 `@numerical-designer`：需要定义——每种塔的2条进化路线的具体属性值、进化费用、进化后的DPS平衡（确保两条路线各有优势场景，无绝对优劣）。

| `td:speed_changed` | 战斗速度切换 |
| `td:tower_evolved` | 塔完成进化 |
| `td:bond_activated` | 武将羁绊激活 |
| `td:stamina_changed` | 体力值变化 |

### 8.4 存档迁移策略

| 旧字段 | 处理 |
|--------|------|
| 无 `stamina` 字段 | 首次加载时初始化为满体力 |
| `DAILY_CHALLENGE_LIMIT` 相关计数 | 废弃，不再读取 |
| 无 `evolutions` 字段 | 初始化为空对象，已有Lv5塔保持未进化状态 |
| 无 `bonds` 字段 | 初始化为空，已部署的武将组合自动检测羁绊 |

## 9. 数值需求摘要（需 `@numerical-designer` 深化）

以下所有数值在本PRD中仅描述目标体验，**不定义具体数值**。需要 `numerical-designer` 提供完整数值规范：

| # | 数值领域 | 体验目标 | 关键参数 |
|---|---------|---------|---------|
| 1 | **武将技能蓄力** | 蓄满频率让玩家每波有2-3次手动操作机会 | 蓄力时间、手动加成倍率、自动释放等待时间 |
| 2 | **紧急技能** | 每关可用1-2次，是辅助而非替代正常防御 | 伤害/效果值、持续时间、冷却时间 |
| 3 | **体力系统** | 日活玩家每天可玩10-15次 | 体力上限、单次消耗、恢复速率 |
| 4 | **练习模式奖励** | 有少量回报但不会成为刷资源最优解 | 奖励倍率（建议20-30%） |
| 5 | **飘字合并** | 高攻速塔不造成视觉轰炸 | 合并时间窗口 |
| 6 | **连杀阈值** | 连杀提示频率适中（每波1-3次） | 时间窗口、各级阈值 |
| 7 | **塔进化属性** | 两条路线各有优势场景，无绝对优劣 | 进化后全属性表、进化费用 |
| 8 | **武将羁绊加成** | 明显但不至于不用羁绊就过不了关 | 各羁绊的具体加成数值 |
| 9 | **Boss专属技能** | 需要针对性策略但不是"不知道就必死" | 召唤频率、技能伤害、冷却时间 |
| 10 | **速度倍率** | 2×感觉快但可控，3×感觉很快但不至于看不清 | deltaTime缩放系数（建议 1.0 / 2.0 / 3.0） |

## 10. 不做什么（Out of Scope）

| 排除项 | 理由 |
|--------|------|
| ❌ 多人对战 / PvP | 复杂度过高，不符合Idle游戏定位 |
| ❌ 无尽模式 | Phase 3之后再考虑，当前先优化有限波次体验 |
| ❌ 新建筑类型 | 13种建筑已足够，通过进化系统增加多样性 |
| ❌ 新敌人类型 | 12种敌人已足够，通过Boss专属机制增加多样性 |
| ❌ 新武将角色 | 不在本PRD范围，武将系统由其他模块管理 |
| ❌ 音效系统 | 当前项目无音效架构，不在本次范围 |
| ❌ 赛季排行榜 | 单机Idle游戏无需竞技排名 |
| ❌ 实时联机协防 | 纯前端架构不支持 |
| ❌ 重做渲染引擎 | 在现有Canvas 2D基础上增量改进 |
| ❌ 修改主线战斗系统 | 塔防是独立子系统，不影响主线 |
| ❌ 使用外部依赖/npm包 | 项目约束：纯前端零依赖 |
| ❌ 修改城镇建筑系统 | TD专用地图与城镇地图独立，不互相影响 |
| ❌ 塔之间的连锁/组合效果 | 进化系统已提供足够策略深度，连锁效果复杂度过高 |
